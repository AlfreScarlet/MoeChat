# 原生 Socket 接口文档

本文档描述 MoeChat 的原生 TCP Socket 接口。该接口提供基于自定义协议的实时语音交互功能，支持文本消息发送和音频流式传输，独立于 HTTP API 服务运行。

---

## 服务信息

| 项目 | 说明 |
|---|---|
| 协议 | TCP Socket |
| 默认端口 | `8002` |
| 连接方式 | 标准 TCP 连接 |
| 超时设置 | 客户端连接超时 5 秒 |
| 最大连接数 | 100（listen backlog） |

---

## 协议格式

### 消息分隔符

所有文本消息以 `<|end|>` 作为分隔符，服务端通过该分隔符识别完整消息的边界。

### 客户端 → 服务端

#### 文本消息

发送文本聊天消息，触发 LLM + TTS 管线处理：

```
<|me|>用户消息内容<|end|>
```

| 部分 | 说明 |
|---|---|
| `<|me|>` | 文本消息前缀标识 |
| 消息内容 | UTF-8 编码的文本字符串 |
| `<|end|>` | 消息结束分隔符 |

#### 音频消息

发送音频数据，用于语音识别（VAD + ASR）：

```
<|audio|>[int16 PCM 二进制数据]<|end|>
```

| 部分 | 说明 |
|---|---|
| `<|audio|>` | 音频消息前缀标识 |
| 二进制数据 | int16 PCM 格式的原始音频字节 |
| `<|end|>` | 消息结束分隔符 |

**音频格式要求**:
- 编码格式: int16 PCM（16 位有符号整数）
- 采样率: 16000Hz
- 数据传输: 原始二进制字节（非 base64 编码）

### 服务端 → 客户端

#### 打断信号

当 VAD 检测到新的语音段落开始时，服务端发送打断信号，通知客户端停止当前播放：

```
<|start|><|end|>
```

#### 识别结果

当 VAD 检测到语音段落结束并完成 ASR 识别后，服务端发送识别出的文本：

```
<|me|>识别出的文本内容<|end|>
```

#### TTS 音频流

当客户端发送文本消息后，服务端通过 `text_llm_tts_v3` 管线流式返回 TTS 合成的音频数据，以二进制形式直接发送（无前缀标识）。

---

## VAD 语音段落检测流程

服务端使用 Silero VAD（`speech_pad_ms=400`）对客户端发送的音频数据进行语音活动检测：

1. 客户端持续发送 `<|audio|>...<|end|>` 格式的音频数据帧
2. 服务端将 int16 PCM 数据转换为 float32 格式后传入 VAD 迭代器
3. 当 VAD 检测到语音段落开始（`"start"` 事件）时：
   - 检查距上次消息的时间间隔，若超过 **1.5 秒**则清空之前的音频缓存
   - 向客户端发送打断信号 `<|start|><|end|>`
   - 开始缓存后续音频数据
4. 当 VAD 检测到语音段落结束（`"end"` 事件）时：
   - 将缓存的音频数据合并为 WAV 格式（PCM_16, 16000Hz）
   - 调用 ASR 引擎进行语音识别
   - 若识别结果非空，向客户端发送 `<|me|>{识别文本}<|end|>`
   - 记录当前时间用于超时判断

### 超时机制

- 若两次语音段落之间的间隔超过 **1.5 秒**，服务端会清空之前缓存的音频数据
- 该机制防止不相关的语音片段被错误拼接

## 完整交互流程示例

```
客户端                                    服务端
  |                                         |
  |--- TCP 连接 (端口 8002) --------------->|
  |                                         |
  |--- <|audio|>[PCM数据]<|end|> --------->|  (持续发送音频)
  |--- <|audio|>[PCM数据]<|end|> --------->|
  |                                         |  (VAD 检测到语音开始)
  |<-- <|start|><|end|> -------------------|  (打断信号)
  |                                         |
  |--- <|audio|>[PCM数据]<|end|> --------->|  (继续发送音频)
  |--- <|audio|>[PCM数据]<|end|> --------->|
  |                                         |  (VAD 检测到语音结束)
  |                                         |  (ASR 识别)
  |<-- <|me|>你好<|end|> ------------------|  (识别结果)
  |                                         |
  |--- <|me|>你好<|end|> ----------------->|  (发送文本消息)
  |                                         |  (LLM + TTS 管线处理)
  |<-- [TTS 音频二进制数据] ----------------|  (流式返回音频)
  |<-- [TTS 音频二进制数据] ----------------|
  |                                         |
```

## 连接与断连处理

### 新连接

- 服务端接受 TCP 连接后，为每个客户端创建独立的守护线程处理
- 客户端连接超时设置为 5 秒

### 正常断开

当客户端正常关闭连接时（`recv` 返回空数据），服务端：
1. 关闭对应的 socket
2. 记录客户端断开日志

### 异常断开

当客户端异常断开时（网络中断、客户端崩溃等），服务端捕获以下异常：
- `ConnectionResetError`
- `OSError`
- `socket.timeout`
- `BrokenPipeError`（发送数据时）

处理行为：
1. 关闭对应的 socket
2. 记录异常断开日志
3. 终止该客户端的处理线程

### chat_proxy 错误

当 LLM + TTS 管线处理过程中发生异常时：
1. 记录错误日志
2. 终止该客户端的连接处理
